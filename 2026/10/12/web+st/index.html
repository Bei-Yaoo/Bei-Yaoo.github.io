MOE之Web入门指导

Web 是建立在互联网之上的一种信息服务
我们平时访问的网站、 浏览器中的管理后台，以及许多手机 APP 的服务端接口，本质上都可能属于 Web 应用

（以下部分内容为moectf中web与渗透入门指南中截取）

虚拟机：

VMWare 虚拟机或者 WSL（Windows Subsystem for Linux）来使用 Linux 操作系统

推荐使用 Kali Linux 这个 Linux 发行版来进行解题辅助和渗透测试

练习资源

https://portswigger.net/web-security

https://www.nssctf.cn/

https://ctf.xidian.edu.cn/games/

等，可自行探索

提问的艺术~~~

1.我正在做什么？

  1. 环境和软件版本是什么？

  2. 我预期发生什么？

  3. 实际上发生了什么？

  4. 我已经尝试了哪些方法？

  5. 我具体不理解哪一步？

  6. 是否附上了代码、请求、响应和报错？

1.完整的错误信息；

2.使用的软件及其版本；

3.操作系统和运行环境；

4.编程语言或框架；

5.希望实现的目标；

6.已经尝试过的方法

完成题目后思考

1.漏洞为什么会出现？

  1. 用户输入经过了哪些处理？

  2. payload 中每一部分有什么作用？

  3. 为什么其他尝试没有成功？

  4. 开发者应该如何修复？

  5. 换一个环境后，这种方法是否仍然有效？

需掌握的基本知识

1.Linux 与计算机基础
学习文件、目录、权限、进程、端口、环境变量以及基础 Shell 命令

2.HTTP 与浏览器
理解 URL、请求方法、请求头、Cookie、Session、状态码和重定向

3.HTML、CSS 与 JavaScript
能看懂页面结构、表单、DOM 操作、事件处理、Fetch 和 JSON

4.一门后端语言
可以从 PHP 或 Python 开始，学习参数接收、文件操作、数据库和 Session

5.数据库与 SQL
掌握增删改查、WHERE、UNION、参数化查询和数据库用户权限

6.编码与数据格式
认识 Base64、URL 编码、HTML 实体、十六进制、JSON、XML 和哈希

常用工具

1.F12 浏览器开发者工具
查看 HTML、JavaScript、HTTP 请求、Cookie 和前端代码，是最容易获得、也最应该先学会的工具。

2.BURP Burp Suite（安全测试平台）
拦截、修改和重放 HTTP 请求。初期可以先学习 Proxy、 HTTP History、Repeater 和 Decoder。

3.CURL curl（命令行工具，与系统进行交互工具）
通过命令行发送网络请求，适合观察请求过程、测试接口和编写自动化流程。

4.CHEF CyberChef（没理解错应该是解码工具）
用于处理 Base64、URL 编码、十六进制、哈希、JSON 和多层编码。

5.VM 虚拟机
VMware 或 VirtualBox 可以提供隔离的实验系统，适合搭建 Kali Linux 等环境。

6.DOCKER Docker
快速运行和销毁本地靶场，减少不同实验环境之间的依赖冲突。

常见web安全问题

这部分内容可查看helloctf或者ctf wiki

1.INFO 信息泄露
HTML 注释、JavaScript、配置文件、备份文件、错误信息或调试接口意外暴露了敏感数据。

2.SQLi SQL 注入
程序将用户输入直接拼接到 SQL 语句中，导致攻击者能够改变原有的数据库查询逻辑。
（SQL为数据库的一种语言，内容变为指令，直接执行，骗数据库）

3.XSS 跨站脚本攻击
应用将未经安全处理的用户输入输出到页面，使浏览器将其作为 HTML 或 JavaScript 解析执行。
（内容变为指令，骗浏览器）

4.CSRF 跨站请求伪造
攻击者诱导已登录用户发送非预期请求，利用了浏览器可能自动携带 Cookie 的特性。
（用户已登录的情况下，骗浏览器使用用户的cookie让服务器开门）

5.FILE 文件上传漏洞
网站没有正确检查上传文件的类型、内容、路径、名称或访问方式，从而产生安全风险。
（传输上去的内容检查疏忽，内容实则为脚本，骗服务器执行。有点misc中隐写的意思（？））

6.PATH 路径穿越与文件包含
用户能够控制文件路径，使程序读取或包含本不应该被访问的文件。
（内容变为指令，查看到不该看的内容）

7.SSRF 服务端请求伪造
攻击者操纵服务器向非预期地址发起请求，可能借此访问服务器所在的内部网络。
（骗服务器发请求，访问内部系统）

8.SSTI 服务端模板注入
用户输入被当作模板代码的一部分解析，导致模板引擎执行非预期表达式或操作。
（将输入的数据当模板代码进行解析）

9.OBJ 反序列化漏洞
程序将外部可控的数据还原成对象时，可能触发危险方法或非预期的程序逻辑。
（输入的内容进行反序列化后会触发删除文件，查看内容等等的危险操作）

10.AUTH 认证与访问控制漏洞
身份验证、Session、JWT 或权限检查存在缺陷，导致用户访问不属于自己的数据或功能。

一些与WEB有关的背景单词

IP—————标识网络中的设备，并负责数据包的寻址与传递

TCP————–建立可靠连接，尽可能确保数据完整、有序地到达 (运输方式)

UDP————-更加轻量、速度较快，但不保证数据可靠到达 (运输方式)

DNS————–将人类容易记忆的域名转换为 IP 地址

HTTP————-在浏览器、客户端与 Web 服务器之间传输数据

HTTPS————使用 TLS 加密保护通信过程的 HTTP (加密的HTTP)

WebSocket——–在客户端和服务器之间建立持续的 (双向通道)

Web是什么

1.前端（FE）：用户看到的部分
前端通常运行在浏览器中，由 HTML（描述页面结构和内容）、CSS（控制页面颜色布局和视觉样式） 和 JavaScript（交互数据请求和动态逻辑） 构成，负责页面结构、样式以及用户交互。

2.后端（BE）：处理逻辑的部分
后端运行在服务器上，负责处理请求、验证身份与权限、 查询数据库并向客户端返回响应
常见的后端语言和框架包括：
PHP Python / Flask Python / Django Java / Spring Node.js Go C# / ASP.NET

3.数据库（DB）：保存数据的部分
数据库用于保存用户账号、文章、权限和配置等信息，常见的有 MySQL、PostgreSQL 和 SQLite
常见数据库包括：
MySQL PostgreSQL SQLite Redis MongoDB

4.协议（PROT）：传递信息的部分
浏览器与服务器通过 HTTP 请求和响应交换数据，它就像客户端与服务器之间往来的信件
客户端↔浏览器↔服务器

HTTP请求方式

GET——–（获取页面或数据）

HEAD——（类似于 GET 请求，返回的响应中没有具体的内容，用于获取报头）

POST——-（提交表单创建数据或执行操作）

PUT——–（更新已有数据）

PATCH—–（是对 PUT 方法的补充，用来对已知资源进行局部更新）

DELETE—–（删除指定数据）

OPTIONS—-（查询服务器支持的通信方式）

TRACE——（主要用于测试或诊断）

CONNECT—-（要求在与代理服务器通信时建立隧道，实现用隧道协议进行TCP通信。极少使用）

HTTP状态码

200———-ok

302/301——重定向到其他位置

400———-格式or参数错误

401———-身份认证未通过

403———-拒绝访问

404———-资源不存在

500———-服务器内部错误

502———-得到错误响应

web安全的多种环节

  1. 用户输入没有被正确检查和处理；
  2. 身份认证机制存在缺陷；
  3. 权限检查不完整；
  4. 敏感信息被暴露在前端；
  5. 文件上传功能缺少限制；
  6. 数据库查询语句被错误拼接；
  7. 模板引擎或解析器被不安全地使用；
  8. 使用了存在已知漏洞的第三方组件；
  9. 服务器配置错误；
  10. 开发过程中遗留了调试接口、源码或备份文件

浏览器开发者工具

按下 F12 或 Ctrl + Shift + I 打开开发者工具

1.Elements / 元素
查看并临时修改 HTML 和 CSS （WEB是什么 章节中前端符号）

2.Console / 控制台
运行 JavaScript、查看日志和错误信息

3.Sources / 源代码
查看和调试网页加载的脚本及其他资源

4.Network / 网络
查看 HTTP 请求、响应、参数和资源加载过程

5.Application / 应用
查看 Cookie、LocalStorage、SessionStorage 等数据
